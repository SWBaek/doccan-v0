# 2026-10-06 MVP 평가 지적 수정

수정 범위는 승인 후 내보내기 실패, 셀 승인 대상 표시, 제안 충돌 처리 세 가지다. 사용자 데이터 대신 `verification/browser-data/fixes-20261006`과 자동 테스트의 임시 Asset을 사용했다.

## 변경

| 지적 | 수정 결과 |
|---|---|
| DB commit 후 JSON 저장 실패 | 승인 응답에 `committed`와 파일별 export revision/오류를 분리했다. 실패한 파일은 이전 내용을 유지하고 UI에 지속적으로 미완료 상태를 표시한다. UI/CLI 재내보내기는 최신 DB만 내보내며 제안을 다시 적용하지 않는다. 내보내기가 계속 실패해도 서버를 다시 열어 상태를 확인할 수 있다. |
| 셀 원본 확인·유지/보류 표시 | 승인 카드에 셀 scope와 실제 셀 내용을 표시하고, 원본 확인 시 셀 index 0도 전달한다. 선택·원본 영역·새로고침에서 셀을 유지한다. 기존 좌표 변환을 그대로 사용하여 표의 BOTTOMLEFT와 셀의 TOPLEFT를 각각 처리한다. |
| 모든 제안의 전역 revision 충돌 | 대상 항목의 최초 스냅샷과 이후 적용·검수·되돌림 이력을 검사한다. 다른 항목의 변경은 허용하고, 같은 항목 변경은 stale로 표시하여 승인을 차단한다. 최신 내용으로 별도 ID의 pending 제안을 만들고 다시 승인하도록 했다. 기존 제안의 revision은 바꾸지 않는다. |

응답 후 UI 갱신이 끝날 때까지 관련 버튼을 비활성화하며, 승인 오류가 발생하면 서버 상태를 다시 조회한다. Windows CLI의 오류 출력도 UTF-8로 통일했다.

변경 파일:

- `candoc/core.py`: export 상태 기록·복구, 원자 교체 실패 정리, 대상별 충돌 검사, 별도 재제안.
- `candoc/server.py`, `candoc/cli.py`: 상태·재내보내기·재제안 API/명령, 충돌 응답.
- `web/app.js`, `web/index.html`, `web/style.css`: 상태 안내, 셀 대상 보존, stale 표시와 명시적 재제안.
- `README.md`, `docs/AGENT.md`, 이 문서: 사용법과 검증 기록.
- `tests/test_regressions.py`: 11개 회귀 테스트.
- `tests/browser-cell-before.js`, `tests/browser-cells.js`, `tests/browser-export-failure.js`, `tests/browser-export-recovery.js`, `tests/browser-stale.js`: 수정 전 재현 및 UI 회귀 스크립트.
- `tests/serve_regressions.py`, `tests/seed_browser_regressions.py`: 시험 전용 서버 실패 주입 및 실제 CLI 제안 생성. 운영 코드에는 실패 주입 기능이 없다.

## 검증 결과

`./.venv/Scripts/python -m unittest discover -s tests -v`: 기존 6개 + 회귀 11개, **17개 통과**. 기존 `tests/test_workflow.py`는 수정하지 않았다. 최종 로그: [all-tests-final.txt](../verification/fixes-20261006/all-tests-final.txt).

회귀 검증은 다음을 포함한다.

- 문서/검수 JSON 각각의 실패, 부분 내보내기, 지속 실패 상태로 재시작, 되돌린 최신 revision의 재내보내기.
- `os.replace` 실패 시 이전 파일 보존과 임시 파일 정리, DB 트랜잭션 실패 시 미반영, export 상태 기록 실패 시 보수적인 pending 응답.
- 재승인 거부와 재내보내기 후 revision·이력·내용의 중복 없음.
- 다른 항목/같은 항목의 동시 승인, 검수만 바뀐 경우와 변경 후 원복한 경우의 stale 처리.
- 최신 내용을 보존하는 새 제안과 별도 승인, 기존 DB의 교정·제안·이력 보존, 실제 HTTP/CLI 오류 및 재시도.

## 시험 재실행

자동 테스트는 위 unittest 명령으로 실행한다. UI 테스트는 시험용 Asset을 준비한 후 아래 서버에서만 실행한다. 실제 `data`에 연결하지 않는다.

```powershell
./.venv/Scripts/python tests/serve_regressions.py
playwright-cli -s=candoc-fixes open http://127.0.0.1:52742
playwright-cli -s=candoc-fixes run-code --filename=tests/browser-cells.js
./.venv/Scripts/python tests/seed_browser_regressions.py stale
playwright-cli -s=candoc-fixes run-code --filename=tests/browser-stale.js
```

실패 복구 시험은 `seed_browser_regressions.py export`로 제안·실패 플래그를 만든 뒤 `browser-export-failure.js`를 실행한다. 시험 서버를 종료·재시작하여 실패가 유지되는 것을 확인하고, 시험 폴더의 `export-fault.json`을 `{}`로 바꾼 뒤 `browser-export-recovery.js`를 실행한다. CLI 도구 종료코드만 보지 말고 각 UI 로그의 `Result`가 `PASS`인지 확인한다.

## 한계와 적용 상태

- 파일 실패는 예외/교체 실패 주입, DB 실패는 SQLite trigger로 재현했다. 실제 디스크 고갈·전원 차단·저장장치 오류 전체를 시험한 것은 아니다.
- 같은 표의 서로 다른 셀도 동일 항목으로 취급하여 충돌시킨다. 구조 편집 지원 범위는 넓히지 않았다.
- 기존 실제 사용자 서버(52741)는 종료·재시작하지 않았다. 수정한 백엔드는 사용자가 기존 서버를 종료한 뒤 `./start.ps1`로 재시작해야 적용된다. 이 과정의 기존 DB 호환성은 임시 사본에서 검증했다.
- 원본 PDF가 없으므로 변환 정확성·원문 일치 여부를 검증한 결과가 아니다.
- 커밋·푸시·배포는 수행하지 않았다.
