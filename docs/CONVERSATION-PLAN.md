# 에이전트 주도 검수 구현 계획

범위: 기존 BatchReview 진단/불변 묶음 제안, Store 개별 제안/승인/undo,
Codex app-server의 격리된 Chat 실행기를 연결한다. 문서 데이터 모델을 추가하지 않는다.

- 공식 model/list를 페이지 단위로 조회하고 모델별 effort만 선택한다. turn/start에
  두 값을 명시하며 턴별 설정을 저장한다. 실행 중 변경은 금지하고 다음 턴부터 반영한다.
- 별도 검수 대화 journal에 현재 대상, 메시지, 제시한 제안의 버전/대상,
  승인 근거와 진행 위치를 저장한다. 실제 적용 이력이 복구 시 기준이다.
- 시작 시 전체 진단을 실행하고 한 묶음씩 모델이 설명/질문/제안한다.
  읽기/제안 도구만 제공하며, 모델은 적용·이동·승인 권한을 받지 않는다.
- 자연어 승인도 앱의 exact-presentation 확인과 기존 승인 경로를 통과한다.
  중복 전송, 중단, 내용 변경, 설명 뒤 짧은 응답, 복수 제안은 보수적으로 재확인한다.
- 대화를 기본 화면으로 두고 원본/현재 내용/정확한 수정안을 연결한다.
  수동 묶음 목록과 기존 개별 교정은 보조 화면으로 유지한다.

제외: 원본 이미지 AI 판독, 요구사항 분석, 영구 삭제/활용 제외 정책,
API 키/Paseo 의존성, 프런트엔드 전면 교체, 원본/실제 교정 데이터 수정,
기존 서버 재시작, 커밋/푸시/배포.

완료 검증: 전체 unittest, 격리 52742 브라우저 대화/선택/승인/재개/undo,
원본 해시 비교, 실제 설치 app-server 연결 및 model/list(모델 호출 없음).
모델 응답은 모의 시험으로 분리하고 실제 유료 턴은 명시 승인 없이는 실행하지 않는다.
