# 검수 화면의 Codex 대화 연결 계획

## 범위와 완료 조건

- Python 서버가 설치된 Codex app-server 하나를 stdio 자식 프로세스로 관리한다. Paseo, 특정 PC 경로, 직접 모델 API 호출, 인증정보 복사에 의존하지 않는다.
- UI는 메시지 전송, 점진 응답, 실행 상태, 세션 재개, 중단과 연결 종료를 제공한다. 전송 시 Asset/ref/cell/revision을 고정한다.
- 앱 중개 도구는 고정 대상 조회와 pending 제안 생성뿐이다. 승인·재내보내기·되돌림은 기존 사용자 UI에 남는다.
- 공식 CLI 0.160.0에서 생성한 스키마 및 동일 태그의 실행기 구현을 기준으로 `environments: []`, read-only, 승인 불허를 적용한다. 내장 외부 도구와 사용자 MCP를 비활성화한다. 확인되지 않은 버전/권한 설정은 fail closed한다.
- 실행 파일·프로젝트·Asset·대화 상태 경로를 설정할 수 있게 하고 다른 PC 설치 절차를 제공한다.

## 제외와 보존

범용 실행기, 자동 승인, 새 로그인/OAuth, API 키, 전체 문서 자동 전송, 커밋·푸시·배포는 제외한다. 기존 서버는 유지한다. 원본 ZIP/source와 실제 교정 DB/JSON은 해시로 보존 여부를 확인하며 모든 변경 시험은 임시 Asset에서 수행한다.

## 검증

기존 17개 테스트와 모의 app-server 회귀 테스트, 시험 서버 UI 흐름을 실행한다. 연결/스트리밍/재개/중단/종료/오류/중복/선택 변경/제안 후 별도 승인/보존을 검증한다. 가능하면 실제 설치된 실행기의 initialize/account/config와 합성 로컬 모델 응답으로 권한 경계를 추가 확인한다. 실제 유료 모델 대화나 신규 로그인은 실행 전에 필요와 시험 범위를 보고하며, 실행하지 않은 경우 명확히 미검증으로 기록한다.
