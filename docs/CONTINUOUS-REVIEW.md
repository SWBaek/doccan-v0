# 연속 검수 사용과 검증

2026-10-06. 구현 기준은 main `d092bb370525ea465d449547949c02386a94b239`이며 착수 시 로컬 변경은 없었다. 기존 서버를 실행 중이었다면 종료 후 `./start.ps1`로 다시 시작해야 새 API와 화면을 함께 사용한다. 아래 검증은 모두 별도 시험 Asset에서 수행했다.

## 한 항목을 검수하고 다음으로 가기

1. 검색 또는 **의심 후보**를 연다. 목록을 선택해도 목록과 필터는 남는다. 검색 결과는 문단의 일치 부분 주변, 셀의 일치 내용과 index·행·열을 보여 준다. **결과 더 보기**로 150건 이후에도 접근한다.
2. 결과 버튼을 클릭하거나 키보드 Tab → Enter로 선택한다. 변환 화면의 항목/셀과 원본 영역·캡처가 연결된다. 겹쳐서 격자에 나오지 않는 셀은 **표 셀** 목록에서 선택한다. 여러 원본 영역은 **원본 위치**에서 전환한다.
3. 현재 내용을 원본과 대조하고 **직접 수정안 작성**에 수정 내용과 이유를 입력한다. **수정 제안 등록**은 문서를 바꾸지 않는다. Codex 연결이 없어도 텍스트와 일반 표 셀에 사용할 수 있다. 유지·보류도 이유를 작성해 제안한다.
4. 원본 옆 **제안 검토**에서 특정 제안의 변경 전후·이유를 확인한다. **이 제안의 원본 확인**은 제안을 닫지 않는다. **이 제안 승인·적용**으로 그 ID의 제안만 확정한다. 현재 선택이 다른 대상이면 먼저 제안의 원본 확인으로 맞춘다. 새 제안 도착은 알림과 목록만 갱신하며 보고 있던 제안을 교체하지 않는다.
5. **다음 대상**으로 계속한다. 목록 이동에는 승인/검수 완료를 기록하지 않는다. **작업 목록**으로 접은 목록을 다시 열 수 있다. 중단 후 같은 브라우저/서버 주소로 돌아오면 목록·필터·현재 선택·검토 제안이 복원된다. 명시적인 URL의 page/ref/cell/loc가 저장 선택보다 우선한다.

변경 전후는 단어 단위로 강조한다. 매우 큰 차이는 계산량을 제한하기 위해 변경 범위를 넓게 강조할 수 있지만 전체 문자열을 생략하거나 정규화하지 않는다. 긴 제안은 검토 영역을 스크롤해서 읽고, 승인 버튼은 그 제안에 붙어 있다. 원본 확대와 캡처 영역도 각각 스크롤할 수 있다.

## 초안과 선택의 안전성

- 페이지·항목·셀·원본 위치 이동은 하나의 선택 세대를 공유한다. 늦은 응답은 최신 선택을 덮지 않는다. 읽는 동안 이전 선택 표시·원본 박스·입력 대상을 비우고 전송/제안을 막는다. 원본 이미지가 아직 로딩 중이면 박스를 먼저 덧씌우지 않는다.
- 수정안·이유·미전송 채팅은 브라우저 localStorage에 작업 공간/Asset/ref/cell 및 기준 항목·검수 기록·대상 이력 번호와 함께 저장한다. 문서 원본과 확정 검수 DB에는 초안을 넣지 않는다.
- A → B → A 또는 새로고침으로 복원할 때 기준이 달라졌으면 경고와 이전 기준을 남긴다. **비교 확인 · 최신 기준으로 초안 계속**을 눌러야 새 기준의 제안/채팅을 보낼 수 있다. 작성 내용은 자동 적용하거나 버리지 않는다. 되돌림으로 값이 같아져도 이력 번호가 바뀌면 재확인한다.
- 제안 등록은 요청 ID와 본문을 함께 보관한다. 결과가 불확실하면 같은 ID로 결과를 확인한다. 서버는 중복 요청을 이미 만든 제안에 연결하고 다른 본문의 ID 재사용은 거부한다. 승인 중 중복 클릭을 막고, 오류 뒤에는 상태를 재조회한다. 승인을 자동 재시도하지 않는다.
- 이미 전송한 채팅의 대상과 중복 방지는 기존 계약을 유지한다. A 전송 중 B로 이동해도 A의 응답/제안은 A에 묶이고, B의 미전송 초안을 지우지 않는다. **AI는 원본 이미지를 보지 않는다.** 채팅은 변환 영역 아래에 열려 원본과 검토/승인 영역을 덮지 않는다.

초안·목록은 이 브라우저의 작업 편의 데이터다. 브라우저 저장소 삭제, 다른 브라우저/주소/작업 공간에는 자동 이전되지 않는다. 저장 공간이 부족하면 보존 실패를 화면에 알린다. 전송 결과가 불확실한 채팅 요청은 기존 sessionStorage 계약을 유지한다.

## 검수 상태와 집계

| 표시 | 의미 |
|---|---|
| 미확인 | 해당 범위에 확정된 판단이 없음 |
| 유지 승인 | 해당 범위의 명시적인 유지 판단 |
| 보류 | 미해결 확인 사항이 남음 |
| 부분 교정 | 지정 부분을 고쳤으며 나머지 확인은 별도 |
| 승인 대기 / 재검토 필요 | 검수 완료 상태가 아닌 **제안 상태** |
| 승인 후 되돌림 | 과거 승인은 이력에 남지만 해당 적용은 되돌렸음 |

표 전체와 셀별 기록을 함께 읽어 **표시 상태만** 계산한다. 표 전체 판단보다 최근인 셀 보류가 있으면 표는 보류, 최근 셀 부분 교정이 있으면 부분 교정이다. 전체 판단 없이 일부 셀만 유지해도 표 전체는 미확인이다. 더 최근의 명시적인 표 전체 판단은 이전 셀 판단을 전체 표시에서 포괄한다. 셀별 기록 자체는 지우지 않으며 셀을 선택하면 확인할 수 있다. 기존 셀 교정 시 표 전체 유지 판단을 무효화하는 동작도 유지한다.

목록의 **판단 기록 수**는 불러온 목록 범위에 직접 저장된 판단이 있는 대상 수다. **유지 수**는 위 집계 규칙의 유지 대상 수다. 보류·부분 교정은 남은 작업에 포함된다. 이것을 문서 전체의 검수 완료 수나 정확도 지표로 사용하지 않는다. 판단 때문에 검색어/의심 조건이 사라져도 시작한 목록을 보존하며, 최신 검색은 사용자가 다시 찾기를 실행한다. 추가 결과를 읽는 중 revision이 바뀌면 서로 다른 시점의 페이지를 섞지 않고 다시 검색하도록 안내한다.

## 유지한 데이터 계약

입력 ZIP, `data/source`, DoclingDocument 배열·참조·위치 연결과 `docling-core==2.93.0` / schema `1.10.0` 계약을 바꾸지 않았다. 표시와 초안을 위해 원본을 정규화하거나 재배열하지 않는다. 새 SQLite `proposal_requests`는 등록 중복 방지용이며 문서/판단 이력 형식을 바꾸지 않는다. 표시용 `review_state`, `target_version`, `capability`, `undone_revision`은 저장된 사실에서 파생한다.

stale 승인은 계속 차단한다. 최신 내용으로 새 ID를 만든 뒤 별도로 승인한다. 같은 표의 다른 셀 간 충돌도 기존 항목 단위 규칙을 유지한다. 승인 후 JSON 내보내기가 실패하면 DB 확정/파일 미완료를 구분하고 **최신 확정 데이터 재내보내기**로 복구한다. 재내보내기로 승인·이력·revision을 늘리지 않는다.

구조/임의 JSON/rich cell/여러 prov 텍스트 편집은 추가하지 않았다. 수정할 수 없는 이유와 셀 선택·원본 확인·보류 등 가능한 행동을 보여 준다. 셀 자체의 페이지 정보가 없고 여러 prov인 표는 셀 페이지를 추정하지 않는다. 표시를 위한 `table_page`를 셀 위치의 증거로 사용하지 않는다.

## 재현 절차와 제한

승인 시험은 실제 사용자 문서에서 실행하지 않는다. 다음 서버는 `verification/browser-data/ux-20261006`와 52742 포트에만 쓰고, 기존 모의 Codex를 사용한다. 첫 실행은 시험 Asset을 만든다. 다른 시험 서버가 52742를 쓰면 먼저 그 시험 서버만 종료한다.

```powershell
./.venv/Scripts/python tests/serve_ux.py
# 별도 터미널
playwright-cli -s=candoc-ux open http://127.0.0.1:52742
playwright-cli -s=candoc-ux run-code --filename=tests/browser-ux-flow.js
playwright-cli -s=candoc-ux run-code --filename=tests/browser-ux-races.js
playwright-cli -s=candoc-ux run-code --filename=tests/browser-ux-decisions.js
```

`browser-ux-before.js`는 기준 커밋의 문제 재현용이며 수정 화면의 통과 시험이 아니다. 브라우저 CLI는 스크립트 실패에도 프로세스 exit code 0을 반환할 수 있으므로 출력의 `Result: PASS`/`Error`를 확인한다. 시험 중단으로 남은 제안은 시험 Asset에서만 정리한다. `browser-ux-final.js`는 남은 시험 제안을 UI로 거절하고 되돌림/내보내기 상태를 확인한다. `browser-ux-long.js`와 `browser-ux-chat-recovery.js`는 긴 문단 표시와 채팅 응답 유실을 각각 확인한다.

내보내기 시험은 시험 폴더의 `export-fault.json`을 `{"file":"document.json"}`으로 두고 `browser-ux-export-pending.js`를 실행한다. 그 상태로 시험 서버만 재시작해 pending을 확인한 뒤 파일을 `{}`로 바꾸고 `browser-ux-export-recovery.js`를 실행한다. 이 주입 코드는 시험 서버에만 있다.

실제 유료 모델 요청, 다른 PC/브라우저 엔진, 실제 디스크 고갈·전원 장애는 이번 검증에 포함하지 않았다. 원본 PDF/OCR의 정확성이나 문서 전체 검수 완료를 검증한 것도 아니다. 초안은 브라우저 저장소 용량에 제한되고 여러 브라우저 사이에 동기화되지 않는다. 사용 중이던 실제 사용자 서버/문서는 시험을 위해 재시작하거나 교정하지 않았다.
