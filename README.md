# CanDoc MVP 1

에이전트가 전체 문서의 의심 항목을 가져와 설명하고, 사용자가 원본을 보며 대화로 수정안을 판단하는 로컬 검수 도구입니다. 승인한 변경만 DoclingDocument 사본에 반영합니다. 요약·윤문·재배열이나 PDF 재변환을 하지 않습니다.

## 실행

Windows PowerShell, Python 3.13을 권장합니다. 이 PC에서는 Python 3.13.5로 검증했습니다.

```powershell
# 프로젝트를 복사한 폴더에서 실행합니다.
./start.ps1
```

브라우저에서 **http://127.0.0.1:52741** 을 엽니다. 터미널을 유지하고 종료할 때 `Ctrl+C`를 누릅니다. 최초 실행은 `.venv`와 Asset을 준비합니다. 기본 문서 검수에는 의존성 다운로드 외에 인터넷, 인증, Docker, 변환 서버가 필요하지 않습니다. 선택 기능인 Codex 대화는 해당 PC에 설치된 Codex와 사용자의 ChatGPT 로그인·인터넷 연결을 사용합니다. 포트 변경: `./start.ps1 -Port 52743`.

Codex 대화를 켜려면 검증된 **Codex CLI 0.160.0**을 설치하고 정상 로그인한 뒤 실행합니다. 새 로그인은 사용자가 터미널에서 직접 수행합니다. API 키를 넣지 않습니다.

```powershell
./start.ps1 -ChatConfig ./config/codex.example.json
```

기본 화면의 **Codex 연결·모델 조회 → 모델과 Reasoning effort 선택 → 검수 시작** 순서로 사용합니다. 목록 조회는 모델을 호출하지 않으며, 검수 시작부터 실제 모델을 호출합니다. 에이전트가 첫 문제와 수정안을 가져오면 “왜 그렇게 생각해?”, “137쪽은 제외해”, “응”, “그대로 둬”, “보류해”처럼 답하세요. 모호한 응답은 재확인하며 앱이 특정 수정안에 연결한 승인만 적용합니다. [대화형 검수·검증 결과](docs/CONVERSATION-REVIEW.md)에 재개·예외·승인 규칙을 정리했습니다. 설치 경로는 [Codex 연결 안내](docs/CODEX-CHAT.md)를 참고하세요. 기존 서버는 자동 재시작하지 않으므로 새 기능을 쓰려면 사용자가 종료 후 위 명령으로 다시 실행하세요.

수동 준비가 필요한 경우:

```powershell
python -m venv .venv
./.venv/Scripts/python -m pip install -r requirements-lock.txt
./.venv/Scripts/python -m candoc.cli init
./.venv/Scripts/python -m candoc.server
```

`init`은 이미 초기화된 Asset을 덮어쓰지 않습니다. `requirements.txt`는 핵심 고정 의존성, `requirements-lock.txt`는 검증 당시 전체 설치 버전입니다.

## 사용 순서

**검수 대화**가 기본 흐름입니다. 검수 시작 시 전체 페이지를 진단하고 한 문제 묶음씩 설명합니다. 원본 버튼으로 해당 영역을 보거나, 전체 대상·변경 전후를 펼쳐 확인하세요. 명확한 판단을 적용한 뒤 다음 문제로 진행합니다. 화면에서 문단·셀을 선택해 새 질문을 보낼 수도 있습니다. 모델은 원본 이미지를 보지 못하므로 불분명한 원문은 사용자가 확인해야 합니다.

**문제 묶음**은 보조 탐색 화면입니다. 반복 헤더·푸터는 재분류안을, 표 셀 겹침·제목 번호/단계 불일치는 검수 요청을 준비합니다. Codex 없이도 **묶음 선택 → 원본 확인 → 예외 제외 → 정확한 대상 목록 승인** 경로를 사용할 수 있습니다. 목록의 `이 문제를 검수 대화에서 열기`로 특정 문제를 다시 논의합니다. 문서 내용은 승인 전 바뀌지 않습니다.

같은 묶음은 한 revision으로 반영하고 한 번에 되돌립니다. 승인 직전 한 대상이라도 바뀌었으면 전부 거부하며 `재진단 후 다시 검토`로 돌아갑니다. 재진단은 기존 유지·보류 기록을 지우지 않습니다. 대표 사례를 확인한 묶음 판단은 개별 항목 검수 완료로 기록하지 않습니다. 실제 138페이지 사본의 진단 근거·화면·시험 결과는 [일괄 검수 안내](docs/BATCH-REVIEW.md)에 있습니다.

`문서 보기`로 전환하면 기존 개별 교정 흐름을 사용할 수 있습니다.

1. **찾기**: 전체 문서를 검색하거나 `의심 후보`를 엽니다. 검색은 일치 부분 주변과 표 셀 index·행·열을 보여줍니다. `결과 더 보기`로 다음 결과를 불러옵니다.
2. **대조**: 작업 목록의 대상을 선택합니다. 변환 내용·원본 영역·현재 셀이 연결되며, 겹친 셀은 셀 목록으로 선택합니다. 복수 원본 위치는 위치 목록에서 전환합니다. 위치가 불명확한 셀의 페이지는 추정하지 않습니다.
3. **작성**: `직접 수정안 작성`에서 내용과 이유를 입력하고 `수정 제안 등록`을 누릅니다. 지원하는 텍스트·일반 셀은 Codex 없이도 동작합니다. 유지·보류 역시 이유를 입력해 제안합니다. 지원하지 않는 대상에는 제한과 후속 행동을 먼저 표시합니다.
4. **검토·승인**: 원본 옆 `제안 검토`에서 특정 제안의 변경 전후·이유를 확인하고 `이 제안 승인·적용`을 누릅니다. 원본을 확인해도 제안을 닫지 않습니다. 새 제안이 도착해도 보고 있던 제안은 유지합니다. 선택 대상이 다르면 `이 제안의 원본 확인`으로 맞춘 뒤 승인합니다.
5. **계속·재개**: 작업 목록의 `이전 대상`·`다음 대상`으로 계속합니다. 이동은 승인이나 완료가 아닙니다. 같은 브라우저/서버에서 새로고침·재접속하면 목록·필터·선택·검토 제안과 대상별 초안을 복원합니다. URL에 페이지·항목·셀이 있으면 그 선택을 우선합니다. `작업 목록` 버튼으로 접어 둔 목록을 다시 엽니다.

초안은 **문서나 검수 DB가 아닌 브라우저 저장소**에 대상·기준 스냅샷과 함께 저장합니다. A에서 작성하다 B를 확인하고 돌아와도 수정안·이유·미전송 채팅을 이어갑니다. 기준 내용/검수 이력이 바뀌면 이전 기준을 보여 주고 재확인을 요구합니다. 자동 적용하지 않습니다. 브라우저 데이터 삭제/다른 브라우저/다른 서버 주소로는 초안이 이동하지 않습니다.

기존 `개별 항목 채팅`은 변환 영역 아래에 열리며 별도 대화 기록을 유지합니다. **AI는 원본 이미지를 보지 않습니다.** 전송한 메시지는 당시 대상에 고정되고, 새 선택은 다음 메시지에만 사용합니다. 외부 에이전트용 요청·self_ref·revision·원시 JSON은 선택 패널의 상세 정보에서 확인합니다.

`의심 후보`는 규칙으로 찾은 확인 대상이며 오류 확정이 아닙니다. 미확인·유지·보류·부분 교정은 검수 상태, 승인 대기·재검토 필요는 제안 상태입니다. 목록의 판단 기록 수는 문서 전체 완료 수가 아닙니다. 표 전체 유지 뒤 더 최근에 셀을 보류하면 표도 보류로 표시합니다. 일부 셀의 유지/교정만으로 표 전체를 완료 처리하지 않습니다. 기존 판단 이력을 바꾸지 않고 표시 상태를 계산합니다.

`변경 이력 → 마지막 적용 되돌리기`로 역순 복구할 수 있습니다. 상세 사용법·집계 규칙·이번 실행 결과·화면은 [연속 검수 안내](docs/CONTINUOUS-REVIEW.md)를 참고하세요.

## 데이터 위치

| 경로 | 역할 |
|---|---|
| `IEEE-1547-2018-document-assets.zip` | 제공된 원본 ZIP, 변경하지 않음 |
| `config/conversion-environments.json` | Asset보다 상위의 사용자 제공 변환 환경 정의 |
| `data/manifest.json` | Asset ID, 환경 ID, 스키마 1.10.0, 원본 파일 SHA-256 |
| `data/source/document.json`, `data/source/artifacts/` | 최초 JSON, 138페이지와 기존 그림 이미지. 앱의 쓰기 대상이 아님 |
| `data/source-links.json` | 최초 self_ref와 원본 prov 연결 |
| `data/work/document.json` | 실제 DoclingDocument 형식의 작업 사본 |
| `data/work/artifacts/` | 작업 JSON의 상대 이미지 URI를 유지하는 독립 복사본 |
| `data/work/review.sqlite3` | 확정 문서 revision, 제안, 승인·거절, 검수 상태와 변경 전후 이력 |
| `data/work/review.json` | 별도 검수 상태 내보내기 |

승인은 SQLite 트랜잭션으로 확정하고 `document.json`과 `review.json`을 각각 원자 교체합니다. 파일 내보내기가 실패해도 이미 확정한 교정은 유지하며, 화면에 **DB 반영 완료 / JSON 내보내기 미완료**와 파일별 revision을 표시합니다. `최신 확정 데이터 재내보내기` 버튼이나 `candoc.cli reexport`로 재시도하세요. 재승인하지 않으며 재내보내기는 교정·이력·revision을 늘리지 않습니다. 재실행 중에도 내보내기가 실패하면 검수 화면을 열어 실패 상태를 확인하고 재시도할 수 있습니다. 화면·API·JSON 다운로드는 DB의 확정 데이터를 표시합니다.

실행 중 `work/document.json`을 수동 편집하면 재실행 시 덮어써지므로 CLI/API로 제안하세요. 작업을 백업하려면 서버를 종료한 뒤 `data` 폴더를 복사하세요. JSON 다운로드는 문서만 내려받으며 이미지는 `work/artifacts`를 함께 보관해야 합니다.

서로 다른 항목의 제안은 다른 제안이 먼저 승인되어도 대상이 변하지 않았으면 승인할 수 있습니다. 같은 항목의 내용·검수 판단·되돌림 이력이 바뀐 제안은 **재검토 필요(stale)**로 표시하며 승인을 막습니다. 최신 내용과 제안 당시 내용을 비교하고 `최신 내용으로 새 제안 만들기`를 누른 뒤, 새 제안을 별도로 승인하세요. 같은 표의 다른 셀도 같은 항목으로 보수적으로 충돌 처리합니다.

## 지원 범위와 한계

- 텍스트: 자식이 없고 prov가 하나인 텍스트 항목의 `text`. `orig`는 보존하고 작업 사본 charspan만 새 길이에 맞춥니다.
- 유형: 자식 없는 `text`, `paragraph`, `title`, `section_header`, `page_header`, `page_footer` 사이의 변경. 제목 단계는 명시적으로 지정합니다. `content_layer`는 별도 의미이므로 개별 유형 변경에서는 보존합니다. 반복 헤더·푸터 묶음 승인은 별도 계약으로 `label`과 `content_layer=furniture`를 함께 바꾸고 `level`을 제거합니다. 부모·자식과 원본 참조는 보존합니다.
- 표: 기존 `table_cells`의 일반 셀 `text` 교정. 0부터 시작하는 **셀 배열 index**로 식별합니다. 행·열 번호와 다릅니다.
- 분리·병합·삭제·재배치·참조 변경, 표 행열/병합 구조, 목록/수식/캡션으로의 유형 전환, 여러 prov의 텍스트 수정, rich cell 수정은 거부합니다. 이 때문에 최초 참조와 위치 연결을 잃지 않습니다.
- 표 셀 자체에는 page_no가 없습니다. 여러 prov의 표에서는 셀의 페이지를 추정하지 않고 표 전체 위치만 제공합니다.
- 실제 입력의 `#/tables/56`에는 셀 범위 겹침이 있습니다. 보존하고 의심 후보로 표시합니다. 공식 HTML 격자가 모든 겹친 셀을 표현할 수 없으므로 셀 목록/JSON으로 확인하며 구조 교정은 보류해야 합니다.
- 공식 HTML은 항목 단위 표시용입니다. 캡션은 별도 항목으로 선택되며, 배열 원본/문서 읽기 순서를 연결해 표시합니다. JSON이 교정 데이터의 기준입니다.
- 로컬 단일 사용자 도구이며 계정 인증을 제공하지 않습니다. 루프백 바인딩·Host/Origin·세션 토큰으로 다른 웹사이트의 쓰기를 차단하지만, 같은 PC의 프로세스가 사용자 승인을 대신하지 않는다는 운영 규칙이 필요합니다.
- 원본 PDF가 없어 원본 전체와의 일치나 변환 정확성은 검증하지 않았습니다. 모든 항목을 사람이 검수한 상태도 아닙니다.
